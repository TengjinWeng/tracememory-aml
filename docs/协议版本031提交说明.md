# 0.3.1-protocol：新版本接入验证

该配置用于用户授权的“先提交版本并跑官方 Smoke”，不提交 Full。
它不调用 LLM、Embedding 或 Reranker；原始图文持久化、完整文本索引、BM25、
像素一致性、受限实体扩展与原始证据返回可独立运行。
平台提供 caption 时可使用该文字；本配置不具备新图像的视觉语义理解。

完整算法开发服务仍为 `0.3.1-system`，单独在 18089 使用 `gpt-5.6-sol` CLI 和本地 Qwen。
两者代码配置、数据目录及 Smoke 记录分开；不得将协议配置的结果当成完整算法成绩。

## 部署与版本边界

- 网关端口 18090，新版本路径 `/v0.3.1-protocol/add`、`/search`、`/health`。
- 现有根路径透传给冻结的 18086 服务；旧版本业务逻辑和数据库不被替换。
- 新配置数据保存在 `data-system/protocol/`；使用完整 user_id 隔离。
- 新版本直接绑定到现有 AML Key。根据官网 UI，鉴权继承原版本，因此新服务使用原接口凭证，私密保存。
- 新配置允许 16 个活动请求，超量返回可重试 429；这不是 Full 容量承诺。
- 同步 Add、幂等 request_id、媒体大小限制和来源返回遵循既有协议。
- 运行依赖 Python、Pillow、NumPy、SQLite；无模型下载或模型 API 成本。
- 每小时清理超过 29 天不活动的作用域；评测结束后可提前按精确作用域清理。
- 进程由 tmux 重启循环恢复，主机重启恢复仍需人工执行。
- ngrok 免费入口的请求和流量配额有限，仅声明 Smoke 接入用途。

启动：`bash scripts/supervise_protocol.sh`（在独立 tmux 会话内）。
私密配置：`secrets/protocol-service.env`，权限 0600。
申请前固定代码 commit，在 `docs/新增协议版本.private.json` 保存绑定回执；
官方 Smoke 按版本保存独立私密回执，先查任务再提交，避免重复。
