# 规则核对与系统边界

核对日期：2026-10-29。按当前官网可见的中文文档、API Guide 和参赛说明核对；
网站采用多页面共用 HTML，模型要求实际位于用户文档，而非此前误指的 API Guide 页面正文。

| 官方要求 | 系统对应措施 |
| --- | --- |
| 参赛方托管 Add/Search，平台执行回答、评分 | 实现 Add/Search 主服务，只返回证据 |
| Add 同步确认并立即可检索 | 持久化与索引全部完成才返回 200，失败返回错误 |
| Search 按相关性排序，数量不超过 top_k | 排序后限制条数，不返回最终答案 |
| user_id 是检索隔离边界 | 数据、缓存、词频和向量索引按完整 user_id 隔离 |
| 图文有序数组，图片必须内联 | 接收 text/image_url 数组；拒绝远程图片地址 |
| JPEG/PNG/WebP；单图 10 MiB、Add 合计 30 MiB | 验证编码、解码体积、签名和实际图像 |
| 学术榜规定 Embedding 与 LLM 型号，Reranker 不限 | 正式适配器固定指定模型；开发模式明确隔离 |
| 数据仅供当前评测任务使用，结束后 30 天内删除 | 不用于训练/外传；按不活动作用域提前清理原文及派生物 |
| 版本固定，Smoke 后再 Full，正式结果需审核 | 保留原申报版本；新系统的正式前置条件仍独立验证 |

当前交付的 `0.3.1-system` 已用 `gpt-5.6-sol` 和本地 Qwen Embedding 完成开发自测。
它不因此获得学术榜模型合规性或官方成绩；开发模式拒收非 `dev:` 的正式评测作用域。
正式模式的指定模型适配、隔离数据库和预检查已经实现，但真实密钥、版本绑定、官方 Smoke、
Full 容量和费用仍需要各自完成。不得把一项接口自测通过，视作所有参赛条件已满足。

原申报的 `0.1.0-protocol` 现已获学术榜准入，且完成官方 Multimodal Smoke，平台记录为通过。
完整算法开发版的合规、版本绑定和 Smoke 仍需单独验证，不能沿用另一个版本的通过记录。
授权后实时合约的并发下限为 16；Smoke 客户端已改为读取该合约，不继续使用早期摘要中的 1 路参数。

本系统只在必要时调用视觉模型，文本写入使用原文和本地向量；生成信息只参与索引。
本地模型可以用于自建数据的开发试验，但模型更换后必须重新建立相应向量索引。
CLI 登录使用现有账号的官方登录方式，没有把 ChatGPT 订阅伪装成指定模型 API Key。

平台 Answer/Eval 的模型凭证由平台管理；供应商模型 Key 不是参评提交字段。
我们的 Add/Search 若调用外部模型，需要自己的可用访问渠道；公开资料未承诺向参赛系统提供模型代理或额度。
详见 `正式模型调用核对.md`。用于新增版本与 Smoke 的 `0.3.1-protocol` 不调用任何模型，
与 CLI 完整算法开发版分别披露、部署和验证，不借协议版的通过记录代替算法版结果。

评测数据不能跨任务/用户复用。开发自测缓存只在本次自建作用域内复用，正式数据库与开发库分开。
自动清理依赖服务持续运行；机器或容器停止后须在重启时及时恢复服务，检查清理状态。
