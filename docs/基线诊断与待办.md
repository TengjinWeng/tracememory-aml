# 等待审核期间的评估与后续工作

本报告只基于独立自建合成数据，不是 AML 数据、不产生官方成绩、不调用模型 API。
原始数据见同目录 `baseline-benchmark.json`；脚本为 `scripts/benchmark_baseline.py`。

## 检索效果诊断

7 个预设问题，各有约 180 条干扰记忆；首位命中 3/7，前五位命中 4/7。
样本很小，仅用于暴露具体缺陷，不能代表比赛准确率或泛化表现。

| 能力 | 当前表现 |
| --- | --- |
| 中英文精确关键词 | 目标证据排第一 |
| 完全相同图片字节 | 目标证据排第一 |
| 同义改写（automobile → car） | 目标未进入前 100 |
| 最新事实 | 旧住址排第一，新住址排第二 |
| 跨会话关联 | 找到“骑车的人是 Alex”，但“Alex 推荐茉莉花茶”仅排第 25 |
| 相同像素、不同 PNG 压缩 | 没有有效匹配信号；目标仅按零分排序排第 45 |

当前实现是接入基线；视觉、语义召回、时序治理、多跳证据扩展都还需要实现或验证。

## 服务器容量诊断

在 gmlab_out_106 的独立临时数据库和回环 HTTP 端口上测量；不触碰正在审核的生产数据库。
数据为短文本，检索串行仅 8 次、四并发仅 12 次；P95 是小样本诊断指标。
以下不含公网隧道、真实尺寸图片或模型调用延迟，不是 Full 容量认证。

| 记忆数量 | 串行检索 P95 | 四并发 P95 | 数据库大小 |
| ---: | ---: | ---: | ---: |
| 100 | 13.58 ms | 93.59 ms | 73,728 B |
| 1,000 | 27.14 ms | 257.23 ms | 544,768 B |
| 5,000 | 74.39 ms | 941.76 ms | 2,646,016 B |

当前检索逐条扫描同一用户的元数据，规模扩大后需改进索引/候选筛选；尚未修改审核中的实现。

## 公网流量风险

按 1 GB = 1,000,000,000 字节估算，以下只算 Base64 图片，忽略文本、JSON 和其他开销：

| 每题返回图片 | 编码流量下界 | 1 GB 理论最多题数 |
| --- | ---: | ---: |
| 1 张 × 256 KiB | 349,528 B | 2,861 |
| 10 张 × 256 KiB | 3,495,280 B | 286 |
| 20 张 × 512 KiB | 13,981,040 B | 71 |

ngrok 免费额度不能直接视为足够 Full。需要先拿到官方任务规模，评估每题实际图片数、
图片预算、无损/有损压缩对证据的影响，再确定公网流量方案。任何付费升级需用户授权。
