# 多模态开发优化 0.3.1

固定模型：Codex CLI `gpt-5.6-sol`，本地 `Qwen/Qwen3-Embedding-0.6B`。
在授权服务器部署，自建数据与正式评测完全分开。

## 本轮修改

1. 取消完整系统的前 16000 字符索引截断，保留来源尾部与视觉 OCR。
2. 原文、caption、OCR 和事实分别分块，采用 384 字符窗口、64 字符重叠，去除重复窗口。
3. 实体二跳采用有界分数提升，避免把一次较弱的关联分数叠加成最高候选。
4. 增加显式的开发索引重建命令，保留原始数据、幂等哈希和已有模型预算。

重建仅允许 dev: 自建作用域，执行前停止开发 API；不会读取旧协议任务数据库。
本次重建 58 条开发记录，新增 CLI 尝试 0。

## 对比方法

`python -m system_service.benchmark_multimodal --label before|after`。
固定的 54 条自建记录包含 5 条原始图像记录及 45 条干扰文本；共有 10 个检索问题。
涵盖相近编号、空间关系、跨语言 OCR、不同像素查询图、时间更新、多跳和长文尾部。
9 个问题需要一条来源，1 个问题需要两条来源。

| 诊断指标 | 修改前 | 修改后 |
| --- | --- | --- |
| 单来源问题，目标排第一 | 2/9 | 7/9 |
| 全部所需来源进入前五 | 10/10 | 10/10 |
| 新增 CLI 尝试 | 6 | 0（复用同作用域缓存） |

这些问题用于发现和修复缺陷，不是独立留出测试，不能推算官方成绩或泛化收益。
修改后的单次耗时多数为热缓存，不能和首次冷缓存请求直接比较速度。
空间左右关系与“当前住址”的第一名仍有错误，下一轮需要继续检查细粒度关系及时间状态。
详细记录见 `multimodal-regression-before.json` 与 `multimodal-regression-after.json`。

开发累计 CLI 尝试 10/20，未清零或提高上限；本轮未调用付费模型 API，也未启动 Full。
